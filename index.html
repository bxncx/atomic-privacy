01 / OVERVIEW

About this policy

Atomic provides security tools for Discord communities, including anti-spam checks, honeypot or suspicious-link detection, and protections against potentially destructive server actions (anti-nuke features).

In this policy, “Atomic,” “we,” or “the bot” refers to the Atomic Discord bot and its operator. Discord is a separate service and its own privacy policy applies to information Discord processes.

Before publishing, replace every highlighted placeholder and verify this page against the bot’s actual code and configuration. This template is not legal advice.
02 / INFORMATION HANDLED

What information may be handled?

To provide the security features described above, Atomic may process or store the following information, depending on which features are enabled in a server:

  • Discord server IDs to identify the server where the bot is installed and associate its configuration.
  • Discord user IDs when needed to identify the account associated with a security event or moderation action.
  • Server settings configured for Atomic, such as feature toggles, thresholds, or other security preferences.
  • Security-event information needed to detect or respond to spam, suspicious links, or potentially destructive actions. Confirm in your implementation whether any event details are saved to disk or logs.
  • Message or link content may be processed temporarily if required for anti-spam or suspicious-link detection. Do not claim it is never processed unless your code and Discord settings confirm that.

Atomic is not intended to collect passwords, payment card details, or the contents of private Discord messages. Do not add such collection without updating this policy and assessing the legal requirements.

03 / PURPOSE

How information is used

  • To identify the Discord server and apply its saved security settings.
  • To detect spam and suspicious or malicious links.
  • To identify potentially destructive server actions and support anti-nuke protections.
  • To help server administrators understand or respond to security events, where the relevant feature is enabled.
  • To troubleshoot errors, maintain the bot, and prevent abuse of its features.

Atomic should process only information reasonably needed for these purposes.

04 / MESSAGE CONTENT

Messages and Discord permissions

Anti-spam and link-detection features may need to inspect message content or links while processing messages. This does not automatically mean the content is stored permanently. Actual processing depends on the bot’s code, enabled Discord intents, and server configuration.

Before publishing, verify whether message content is only checked in memory, written to logs, or saved in a JSON/database file. If content is stored, state what is stored, why, and for how long.

05 / DISCLOSURE

When information is shared

Atomic does not sell personal information. Information may be processed by Discord as part of providing the Discord platform, and by the hosting or infrastructure providers used to run Atomic. Information may also be disclosed when required by law or necessary to address abuse, protect users, or secure the service.

Only name specific providers here after confirming which providers the bot actually uses.

06 / RETENTION

Storage, retention, and deletion

Configuration and identifier data may be stored while Atomic is installed on a server and needed to provide its features. The actual retention period depends on the bot’s implementation and operational logs.

Before publishing: set and document a real retention rule. For example, decide what happens to saved server settings when the bot is removed, whether security logs expire, and how an administrator can request deletion. Do not leave retention undefined in your actual operating practice.

For data requests, contact the operator using the contact details below and include the relevant server ID and a description of the request. Do not send passwords or authentication tokens.

07 / SAFEGUARDS

How information is protected

Reasonable technical and organizational safeguards should be used to protect stored data, restrict access, and keep bot credentials confidential. No online service can guarantee absolute security.

Never publish bot tokens, API keys, private configuration files, or database/JSON files containing server data in the website repository. Keep credentials outside public source code.

08 / YOUR CHOICES

Your choices and privacy requests

Server administrators can remove Atomic from their server and change the bot’s available settings. You may contact the operator to ask what information is held about a relevant Discord ID, request correction where applicable, or ask for deletion, subject to applicable law and legitimate security or legal needs.

If you are in the European Economic Area, applicable data-protection law may provide additional rights. Which rights apply depends on the circumstances and the operator’s role under the law.

09 / AGE

Children’s privacy

Atomic is a Discord server security tool, not a service designed to collect information directly from children. If you believe information has been stored inappropriately, contact the operator so the issue can be reviewed.

10 / UPDATES

Changes to this policy

This policy may be updated as Atomic’s features or data practices change. The “Last updated” date at the top should be revised whenever the policy changes. Significant changes should be communicated appropriately.
